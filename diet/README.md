## 二、内容结构（56 条，每天 8–9 个板块）
- `blocks[0]` 🛒 顺手备一点 —— **会被渲染到最底部**（`todayContent()` 把 blocks[0] 当收尾）
- `blocks[1]` 📅 今日热量预算（阶段 + 三餐分配条）
- `blocks[2]` ⚖️ 称重日 —— **仅每周第 1 天有**
- `blocks[3]` 🌅 早餐 / `blocks[4]` 🍱 午餐·外卖点单 / `blocks[5]` 🌙 晚餐
- `blocks[6]` 🥤 加餐·饮品 / `blocks[7]` 🌶 辣味加成 / `blocks[8]` 🏃 运动 + 关键动作

菜品库：早餐 14 种、午餐 28 种（**全部是深圳能点到的外卖**，每条带「点单口令」）、晚餐 28 种、加餐 14 种。
加餐由脚本按「热量不超预算、优先高蛋白」自动配平，所以每天总热量都精确落在周目标 ±30 kcal。

## 三、轮换逻辑（改了 index.html）
`contentIdx()` 里 diet 走**独立分支**，不走 `dateIndex()`：
```js
if(id==='diet'){
  if(!DB.dietStart){ DB.dietStart = todayStr(); save(DB); }
  return Math.max(0, dayDiff(new Date(), new Date(DB.dietStart+'T00:00:00'))) % arr.length;
}
```
- 计划起始日存在 `DB.dietStart`，**首次打开新版模块 = Day 1**，之后按顺序走完 56 天。
- 56 天走完会回到 Day 1（循环），届时应根据用户实际体重重新生成一轮。
- 想手动重置起始日：浏览器控制台执行 `DB.dietStart='2026-09-02';save(DB);location.reload()`。

### 注入脚本的坑（已踩过）
整体替换数组时 `new_src = src[:start] + frag + src[end+1:]`：
- `src[:start]` 停在 `[` 之前，`frag` 自带 `[ ]`，后半段必须从 **`end+1`**（跳过原来的 `]`）开始，
  否则会得到 `]],` 语法错误。
- 追加（不清空）时则是 `src[:end] + "," + frag + src[end:]`，别混用。
