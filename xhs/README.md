# 社媒内容模块 = 小红书 GEO 日更

模块 id 仍为 `social`（模块名「社媒内容」不变），内容已从**抖音周更**改为**小红书 GEO 日更**。

## 一、内容规则（每次更新必读）

**定位**：GEO（生成式引擎优化）垂类账号，第一人称「我」，读者是市场/SEO/增长同行 + 中小企业老板。
**这是个长期账号，不做完 30 天就停。**

**关于「30 天」的正确用法（2026-09-03 用户拍板，务必遵守）**：
- 30 天 = **冷启动期**的第一个台阶，**不是账号的生命周期**。1000 粉是阶段目标，不是 deadline。
- 内容里**不要反复强调 30 天**，不要写「Day N / 30」这种带分母的进度——跑到 Day 31 会穿帮，
  而且会让读者觉得这是个限时实验号，不利于长期关注。
- `Day N` **只是连载序号，一直往下数**（Day 31、Day 100…），删掉分母即可，不要改成别的编号方式。
- **对外发布的正文（blocks[2]）尤其不要承诺「我准备花 30 天…」这类话**——长期账号不该给自己设终点。
- 进度板块标题统一写：`🎯 Day N · 阶段目标 1000 粉`。

每天产出 1 篇，5 个板块固定结构（`blocks` 顺序）：

| 顺序 | 板块 | 作用 | 渲染位置 |
|---|---|---|---|
| blocks[0] | 🎯 Day N · 阶段目标 1000 粉 | 收尾 | **最底部**（`todayContent()` 会把 blocks[0] 放最后） |
| blocks[1] | 📕 今日选题 | 标题 3 选 1 + 封面建议 + 跟谁说话 | 主内容 |
| blocks[2] | ✍️ 正文文案（可直接复制） | **textarea 纯文本，点一下全选** | 主内容 |
| blocks[3] | 🏷️ 标签 & 💬 互动钩子 | 10 个标签 + 预埋评论 + 回复话术 | 主内容 |
| blocks[4] | 📈 今日涨粉动作 | 发布时段 + 评论区动作 + 复盘指标 | 主内容 |

### 文案要求（决定能不能涨粉）
1. **正文 280–380 字**（2026-09-07 改：原 500–700 字太长完读率差，被识别为营销号），口语化、**每段 1–2 句强制空行**；开头 3 行必须有具体场景（人名/地名/对话/数字）。
2. **情绪优先于知识**：先让人「被说中」，再给方法。共鸣点优先选：被老板问住的瞬间、做了很久的事突然失效、同行都在装懂。
3. **结尾必须是零门槛互动**：从「互动钩子 6 种池子」里轮换，**连续 3 篇不能重复**。不要问「你怎么看」。
4. **标签固定结构**：2 个赛道大词 + 2 个专业词 + 3 个平台词（DeepSeek/豆包/元宝/Kimi/百度AI搜索，**每篇最多列 3 个，不要 5 个全列**）+ 3 个流量词。
5. **不编造精确数字**。市场规模各家口径差很大，用「量级 + 趋势」表述；拿不准的年份、人名、营收一律模糊化。官网可查的事实（产品名、发布时间）可以写。
6. 每隔几天要有 **1 篇争议/反共识** 内容（如「SEO 已死了吗」「这类企业别做 GEO」），评论区吵起来 = 涨粉最快。
7. **每篇必须包含 ≥ 2 个具象细节**（人名/地名/数字/场景）——破"营销词典感"。详见下面「易收录规范」。

### 封面规范（硬性，2026-09-03 拍板，2026-09-07 重大调整）

> **重大调整原因**：原"白底 + 纯黑大字报"模板在 2024 年起被小红书算法明确打压——
> 5 篇全用这个模板后，5 篇 0 数据。必须换成"真实感"封面。

- **一律竖图 3:4，1080×1440px。这是默认，不要写「横图竖图都行」。**
  - 3:4 在小红书双列信息流里展示面积最大：比 1:1 方图多约 25%，比 4:3 横图多约 40%。
  - 4:3 / 16:9 横图在信息流里被压得很小，封面大字基本看不清，**明确不推荐**。
  - 1:1 方图只在这两种情况才建议：干货多图页（第 2 张往后）、需要左右对比的图。且字号要比 3:4 放大约 1.2 倍。
- **安全区**：画面**底部 15%（1080×1440 下约 216px）必须留空**——信息流里这块会被笔记标题 + 点赞栏压住。
  主文案放画面**中上部**（纵向 1/4 到 1/2 处），四周再留 6%–8% 边距。
- **版式 · 4 种模板按场景轮换**：

| # | 模板 | 占比 | 适用场景 | 优势 |
|---|---|---|---|---|
| **A** | **真实场景照 + 文字 overlay** | 60% | 日常干货、共鸣、清单型 | 「真人原创」识别概率最高 |
| **B** | **手写笔记截图** | 20% | 实操、工具、清单型 | 视觉错位感强，容易在信息流抓眼球 |
| **C** | **真实聊天截图** | 10% | 共鸣、争议、客户故事 | 2025 年起小红书流量倾斜的封面类型 |
| **D** | **白底 + 黑色大字**（旧模板） | 10% | **仅限争议/反共识型** | 这类内容本身有立场，需要"大字标题"镇场 |

> ⚠️ **日常内容禁止用模板 D**——这就是被算法打压的"营销号封面"。
> **A/B/C 三种"真实感"模板**才是破限流的封面方向。

- **多图**：封面和正文页**保持同一个 3:4 比例**，滑动时不跳动。

#### 必带具象细节（破"营销词典感"）

每篇正文**必须包含至少 2 个**具体细节，三选一或组合：

- **具体人名 + 场景**：朋友 / 客户 / 老板的真名或化名 + 具体事件
  - 范例：「我有个做服装代工的朋友老张，昨天吃饭说他们 AI 里搜不到」
  - 反例：「很多企业主反映搜不到」
- **具体地名 / 行业 / 数字**：深圳华强北 / 广州十三行 / 食品代工 / 母婴用品等
  - 范例：「上周去华强北见客户，一个做充电宝的老板」
- **具体场景 / 对话**：开会 / 复盘 / 打电话 / 看后台数据

#### 真实感细节（破"完美文风"）

每篇正文**至少留 1 个**「不完美的小细节」：

#### 5 个最容易踩的"营销号"信号（自查用）

2. ⬜ 全文没出现一个具体人名 / 地名 / 数字

## 三、长期选题机制（Day 31 起走这套，账号一直做下去）

**核心文件**：`evergreen_topics.md` —— 50+ 个常青选题，分 7 类（科普 / 实操 / 工具 / 案例 / 商业 / 动态 / 互动）。

**取题优先级**（长期内容的配比）：

| 来源 | 占比 | 说明 |
|---|---|---|
| 常青选题池 `evergreen_topics.md` | 60% | 基本盘。**可以重复讲，但必须换角度，间隔 ≥ 3–4 周** |
| 评论区 / 私信真实提问 | 25% | 转化最好——用户问什么就写什么，而且自带互动 |
| AI 搜索行业动态 | 15% | 时效性强容易爆，**写前必须联网核实**，不编精确数字 |

**取题流程（Day ≥ 31）**：
1. 打开 `evergreen_topics.md`，从还没取过（或取过但间隔已 ≥ 3–4 周）的题里挑一个。
2. 优先补评论区真实提问——有人问就先写那个，比池子里的题转化好。
3. 每 7–10 天安排 1 篇行业动态类（N1–N4），保持账号"在线"感。
4. 取走后在 `evergreen_topics.md` 的「已取记录」记一行（日期 / Day / 选题编号 / 这次的角度）。
5. 同时也要在 `topic_log.md` 的「已发记录」追加一行——**两个台账都要记**，否则会重复选题。

**周期性动作**（不用等 30 天到点）：
- 每月做一次数据复盘（对应 S5 / Day 26 那类内容）。
- 「5 个 AI 同时问」这类实测（C7 / T2）每隔 1–2 个月复测一次，本身就是一个系列。

### 脚本说明
- `schedule.py [--date YYYY-MM-DD] [--have d1,d2] [--json]`：算今天该备哪几天
- `check_words.py [json] [--strict]`：违禁词扫描，发布区有 P0 命中就退出码 1
- `append_xhs.py <json> [--reset] [--all]`
  - 只填 json：仅注入，适合本地预览
  - `--reset`：先清空 `CONTENT.social` 再追加（换赛道时用，**慎用**）
  - `--all`：注入 + 升缓存 + 同步 dist + 提交推送
  - 会自动备份 `content.js.bak_xhs`，语法校验失败自动还原
  - json 里带 `date` / `day` 字段时按字段写入，不带则 day = 长度 + 1
- `deploy.sh "提交信息"`：升 sw 缓存版本 → 同步 dist → `git pull --rebase` → 再同步 dist → push

### 违禁词规范（硬性，2026-09-04 建立）

起因：Day 1 / Day 2 笔记发布成功但被屏蔽，长时间 0 浏览——文案踩了
**绝对化承诺 + 站外引流 + 数据承诺**三类词。**发布区 P0 必须为 0。**

- 词表与替换建议：`banned_words.md`（改词表改 `check_words.py` 的 `WORDS`）
- 三类高频雷：站外引流（微信 / 加V / 私信我 / 二维码）、绝对化（保证 / 一定 / 100%）、
  极限词（最好 / 第一 / 顶级 / 全网）
- 检查脚本会**区分发布区和内部区**：标题 / 正文 / 标签 / 封面是发布区，命中必须清零；
  「今日选题」「涨粉动作」这类工作台内部看的板块只提示、不阻断

## 五、代码相关（改了这里要同步）
- `content.js` 的 `CONTENT.social`：`title` 存 `Day N · 社媒内容`，`tag` 存当天主题，
  另有 **`date`（计划发布日 YYYY-MM-DD）** 和 **`day`（连载序号）** 两个字段。
- `index.html` 的 `contentIdx()`：**social 走 `socialIdx(arr)`** —— 取「date ≤ 今天」的最后一篇。
  这样提前备好的未来篇目不会自动跳出来抢位置，但可以在详情页的**篇目条**里点开预览。
  前端还会在篇目条上标「今天 / 已发 / 待发」，待发篇目提示「可先做主图」。
- 内容只允许**追加**，不要截断数组（截断会让篇目错位）。30 篇约 150KB，可接受。
- 自动化的 `pick`（手动切换的篇目）只在当天有效，跨天会被清除。
- 发布后 Pages 有几十秒延迟，`curl` 验证要等一会儿。
