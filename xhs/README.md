## 一、内容规则（每次更新必读）

**定位**：GEO（生成式引擎优化）垂类账号，第一人称「我」，读者是市场/SEO/增长同行 + 中小企业老板。
**这是个长期账号，不做完 30 天就停。**

**关于「30 天」的正确用法（2026-09-03 用户拍板，务必遵守）**：
- 30 天 = **冷启动期**的第一个台阶，**不是账号的生命周期**。1000 粉是阶段目标，不是 deadline。
- 内容里**不要反复强调 30 天**，不要写「Day N / 30」这种带分母的进度——跑到 Day 31 会穿帮，
  而且会让读者觉得这是个限时实验号，不利于长期关注。
- `Day N` **只是连载序号，一直往下数**（Day 31、Day 100…），删掉分母即可，不要改成别的编号方式。
- **对外发布的正文（blocks[2]）尤其不要承诺「我准备花 30 天…」这类话**——长期账号不该给自己设终点。
- 进度板块标题统一写：`🎯 Day N · 阶段目标 1000 粉`。

每天产出 1 篇，5 个板块固定结构（`blocks` 顺序）：

| 顺序 | 板块 | 作用 | 渲染位置 |
|---|---|---|---|
| blocks[0] | 🎯 Day N · 阶段目标 1000 粉 | 收尾 | **最底部**（`todayContent()` 会把 blocks[0] 放最后） |
| blocks[1] | 📕 今日选题 | 标题 3 选 1 + 封面建议 + 跟谁说话 | 主内容 |
| blocks[2] | ✍️ 正文文案（可直接复制） | **textarea 纯文本，点一下全选** | 主内容 |
| blocks[3] | 🏷️ 标签 & 💬 互动钩子 | 10 个标签 + 预埋评论 + 回复话术 | 主内容 |
| blocks[4] | 📈 今日涨粉动作 | 发布时段 + 评论区动作 + 复盘指标 | 主内容 |

### 文案要求（决定能不能涨粉）
1. **正文 500–700 字**，口语化、短句、多空行；开头 3 行必须有冲突或悬念（信息流只显示前 3 行）。
2. **情绪优先于知识**：先让人「被说中」，再给方法。共鸣点优先选：被老板问住的瞬间、做了很久的事突然失效、同行都在装懂。
3. **结尾必须是零门槛互动**：扣 1 / 报行业 / 二选一，不要问「你怎么看」。
4. **标签固定结构**：2 个赛道大词 + 2 个专业词 + 3 个平台词（DeepSeek/豆包/元宝/Kimi/百度AI搜索）+ 3 个流量词。
5. **不编造精确数字**。市场规模各家口径差很大，用「量级 + 趋势」表述；拿不准的年份、人名、营收一律模糊化。官网可查的事实（产品名、发布时间）可以写。
6. 每隔几天要有 **1 篇争议/反共识** 内容（如「SEO 已死了吗」「这类企业别做 GEO」），评论区吵起来 = 涨粉最快。

### 封面规范（硬性，2026-09-03 拍板，每篇必带）

- **一律竖图 3:4，1080×1440px。这是默认，不要写「横图竖图都行」。**
  - 3:4 在小红书双列信息流里展示面积最大：比 1:1 方图多约 25%，比 4:3 横图多约 40%。
  - 4:3 / 16:9 横图在信息流里被压得很小，封面大字基本看不清，**明确不推荐**。
  - 1:1 方图只在这两种情况才建议：干货多图页（第 2 张往后）、需要左右对比的图。且字号要比 3:4 放大约 1.2 倍。
- **安全区**：画面**底部 15%（1080×1440 下约 216px）必须留空**——信息流里这块会被笔记标题 + 点赞栏压住。
  主文案放画面**中上部**（纵向 1/4 到 1/2 处），四周再留 6%–8% 边距。
- **版式**：白底 / 米黄底 + 纯黑大字为主，字大到缩略图里也看得清；别用花哨模板，「朴素大字报」更扎眼。
  主标题 8–18 字，副标题补充说明，不要超过 2 行。
- **多图**：封面和正文页**保持同一个 3:4 比例**，滑动时不跳动。

## 三、长期选题机制（Day 31 起走这套，账号一直做下去）

**核心文件**：`evergreen_topics.md` —— 50+ 个常青选题，分 7 类（科普 / 实操 / 工具 / 案例 / 商业 / 动态 / 互动）。

**取题优先级**（长期内容的配比）：

| 来源 | 占比 | 说明 |
|---|---|---|
| 常青选题池 `evergreen_topics.md` | 60% | 基本盘。**可以重复讲，但必须换角度，间隔 ≥ 3–4 周** |
| 评论区 / 私信真实提问 | 25% | 转化最好——用户问什么就写什么，而且自带互动 |
| AI 搜索行业动态 | 15% | 时效性强容易爆，**写前必须联网核实**，不编精确数字 |

**取题流程（Day ≥ 31）**：
1. 打开 `evergreen_topics.md`，从还没取过（或取过但间隔已 ≥ 3–4 周）的题里挑一个。
2. 优先补评论区真实提问——有人问就先写那个，比池子里的题转化好。
3. 每 7–10 天安排 1 篇行业动态类（N1–N4），保持账号"在线"感。
4. 取走后在 `evergreen_topics.md` 的「已取记录」记一行（日期 / Day / 选题编号 / 这次的角度）。
5. 同时也要在 `topic_log.md` 的「已发记录」追加一行——**两个台账都要记**，否则会重复选题。

**周期性动作**（不用等 30 天到点）：
- 每月做一次数据复盘（对应 S5 / Day 26 那类内容）。
- 「5 个 AI 同时问」这类实测（C7 / T2）每隔 1–2 个月复测一次，本身就是一个系列。

### 脚本说明
- `append_xhs.py <json> [--reset] [--all]`
  - 只填 json：仅注入，适合本地预览
  - `--reset`：先清空 `CONTENT.social` 再追加（换赛道时用，**慎用**）
  - `--all`：注入 + 升缓存 + 同步 dist + 提交推送（等价于注入后再跑 deploy.sh）
  - 会自动备份 `content.js.bak_xhs`，语法校验失败自动还原
- `deploy.sh "提交信息"`：升 sw 缓存版本 → 同步 dist → `git pull --rebase` → 再同步 dist → push（rebase 会重写 root 文件，所以 dist 要同步两次）

## 五、代码相关（改了这里要同步）
- `content.js` 的 `CONTENT.social`：`title` 存 `Day N · 社媒内容`，`tag` 存当天主题。
- `index.html` 的 `contentIdx()`：**social 走 `arr.length - 1`（永远显示最新一篇）**，不走 `dateIndex()`。
  这样自动化断更时会停在最后一篇，不会重复推旧内容。
- 内容只允许**追加**，不要截断数组（截断会让 "最新一篇" 错位）。30 篇约 150KB，可接受。
- 发布后 Pages 有几十秒延迟，`curl` 验证要等一会儿。
